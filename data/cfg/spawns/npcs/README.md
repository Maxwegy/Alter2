# NPC spawns

One file per 64x64 map region: `<regionId>.json`, where `regionId = ((x >> 6) << 8) | (z >> 6)`
(the engine's `Tile.regionId`). The server reads every file once at boot (`NpcSpawnsPlugin`) and never
writes them. Any invalid entry stops the boot with every problem logged; a missing directory only warns.

```json
{
  "schemaVersion": 2,
  "regionId": 12850,
  "spawns": [
    {
      "id": "m56d8a069f0b8",
      "npc": "npc.hans",
      "x": 3221,
      "z": 3219,
      "height": 0,
      "walkRadius": 0,
      "direction": "EAST",
      "source": {
        "kind": "manual"
      },
      "note": "migrated from content/areas/lumbridge/npcs/HansPlugin.kt"
    }
  ]
}
```

- `id`: the entry's stable id, `^[wm][0-9a-f]{12}$`, unique across all files (see below).
- `npc`: an RSCM name from `data/cfg/rscm/npc.rscm`, written as the canonical (first) name for its id.
- `x`, `z`, `height` (0-3): the spawn tile; the entry must lie in the file's region.
- `walkRadius` (>= 0): how far the NPC may wander from its spawn tile.
- `direction` (optional): `NORTH_WEST`, `NORTH`, `NORTH_EAST`, `EAST`, `SOUTH_EAST`, `SOUTH`, `SOUTH_WEST` or
  `WEST`; absent means `SOUTH`, as `spawnNpc` does.
- `source`: an object whose `kind` says where the entry came from:
  - `{ "kind": "manual" }`: written by hand.
  - `{ "kind": "wiki", "page": "https://oldschool.runescape.wiki/w/<Page>", "map": "<verbatim {{Map|...}}>" }`:
    generated by `spawnSync`; optional `mapId` and `rule` record why an entry off the surface map was accepted.
  - `{ "kind": "edit", "at": "<ISO-8601 instant>", "page": ..., "map": ... }`: changed or added in game and applied
    by `spawnSync --apply-edits` at `at`; `page` and `map` are the wiki source it was generated from before its
    first edit (absent for edited manual entries and in-game adds).
- `note` (optional): free text.

The same NPC may not appear twice on one tile. Entries are kept in canonical order (x, z, height, npc, then
manual before edit before wiki) with `\n` line endings; `NpcSpawnDataTests` checks all of this.

## Ids

Ids are derived from content, so every tool computes the same id for the same spawn (`SpawnIds`):

- wiki entries: `"w"` + the first 12 hex digits of `sha256("<page>\n<npc>\n<x>\n<z>\n<height>")`, with the full
  page URL and the tile the `{{Map}}` feature gives. Regenerating the same feature gives the same id.
- every other entry: `"m"` + the first 12 hex digits of `sha256("<npc>\n<x>\n<z>\n<height>\n<salt>")`, minted once
  and never recomputed. The salt is `schema1` for the entries converted by `--migrate` and the edit's `at` for
  spawns added in game.

An edit keeps the entry's id, so an edited wiki entry keeps its `w` id after it moves.

## Generated entries

`./gradlew :alter-data:spawnSync` rewrites every `wiki` entry from the infobox `{{Map}}` templates and never
changes a `manual` or `edit` entry. A regenerated wiki entry is dropped when a manual or edit entry carries its id
(the feature was edited in game, so its wiki twin never comes back), or when a manual or edit entry for the same
npc and height lies within the larger walk radius. An edit entry whose wiki feature is no longer generated is kept
and listed under "Edit origins no longer generated" in the report. To change a generated spawn by hand, turn it
into a `manual` entry.

Schema 1 files (`source: "manual"` or `{ page, map }`, no ids, optional `origin`) are no longer read; convert them
once with `./gradlew :alter-data:spawnSync -PspawnArgs="--migrate"` (offline, no cache). An entry with `origin` is
not migrated automatically and must be converted by hand; a second run reports "already schema 2" and writes
nothing.

## In-game edits

In game, `::spawninfo`, `::setwander <n>` and `::setdirection <DIR>` (dev power) act on the NPC on your tile:
`::spawninfo` prints the entry's id and kind and its source; the other two change the live NPC and append one line
to the runtime outbox `data/run/spawn-edits.jsonl`, never to these files:

```json
{"at":"2026-10-10T12:00:00Z","npc":"npc.hans","id":"m56d8a069f0b8","from":{"x":3221,"z":3219,"height":0,"walkRadius":0,"direction":"EAST"},"to":{"x":3221,"z":3219,"height":0,"walkRadius":5,"direction":"EAST"},"regionId":12850,"source":"manual"}
```

`from` is `null` for an add (its id minted from `at`), `to` is `null` for a removal; both `null` is rejected.
`source` is the entry's kind (`"manual"`, `"edit"`) or, for a wiki entry, its page. `./gradlew :alter-data:spawnSync
-PspawnArgs="--apply-edits"` (offline) applies the outbox in order. It finds each line's entry by `id`; a line
without an id (written before schema 2) matches on `(npc, from.x, from.z, from.height)`. An add inserts a new
`edit` entry (rejected when its id exists or the npc already spawns on that tile); a removal deletes the entry; any
other line keeps the id, moves the entry to another file when its region changes and makes it an `edit` entry with
its former wiki page and map. Lines that match nothing, whose id belongs to another npc, or that would put the same
NPC twice on a tile are listed in `data/reports/spawn-apply-edits-<ts>.md` and skipped. The applied outbox is kept
as `spawn-edits.applied-<ts>.jsonl`.

Add spawns here, not with `spawnNpc` in plugin code. Edit on a branch; `spawnItem`/`spawnObj` still live in
plugins.
